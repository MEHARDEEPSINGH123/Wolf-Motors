NAVIGATION
Do not repeat one navbar across all sections. Storefront gets an editorial automotive header; CRM gets lead-focused workspace navigation; analytics gets dashboard navigation and date controls; fleet/operations gets task-oriented navigation; ecommerce gets its own store navigation. Keep shared design tokens but adapt layout and information density.

TECHNICAL TARGET
Prefer Next.js 15, React 19, TypeScript, Tailwind CSS v4 when compatible with the existing repository. Inspect package.json, routes, components, scripts, and installed packages before edits. Reuse working code; do not perform unnecessary upgrades. Use existing chart libraries where possible.

QUALITY
Mobile-first layouts, accessible names and focus states, keyboard usability, sufficient contrast, reduced-motion support, optimized images, useful alt text, consistent SGD/date formatting, validation, loading/empty/error states, meaningful interactions, no dead buttons, and no horizontal overflow. Tables should have responsive treatment. Metrics should be calculated from the dataset, not arbitrary hard-coded values.

DEMO / PRODUCTION LIMITS
Every record, rate, booking, customer, transaction, product, and metric is fictional demo data. Availability is not live. Policies concerning driver eligibility, insurance, deposits, cancellations, privacy, tax, and cross-border travel require Singapore-specific review. Do not accept real payments or claim live integration. Production requires server-side booking validation, concurrency-safe reservations, authentication, authorization, audit logs, payment provider integration, privacy/security review, monitoring, and backups.

SUGGESTED BUILD ORDER
Inspect repository and data; define types/helpers; build design tokens and original WOLF identity; build storefront/catalogue/quote flow; booking demo flow; CRM; analytics; fleet/maintenance/inventory; ecommerce; test routes and responsive behavior; report actual test/build results and limitations.

ACCEPTANCE
Brand/tagline consistent; original wolf mark; all 8 categories present; all major workspaces usable; JSON relationships resolve; quote totals update with dates/vehicle/add-ons; CRM and inventory actions work in demo mode; analytics derive from data; each workspace has distinct navigation; demo limitations are clear; build/tests are honestly reported.
